# TalentSync

Simple microservices project for job posting and recruitment tracking.

## Services

1. Eureka Server - `8761`
2. Auth Service - `8081`
3. Job Service - `8082`
4. Application Service - `8083`
5. Recruitment Service - `8084`
6. API Gateway - `8085`

User, job, and application data is stored in PostgreSQL. The default connection is `localhost:5432`, database `talentsync`, username `postgres`, password `postgres`. You can change it with `DB_URL`, `DB_USERNAME`, and `DB_PASSWORD` environment variables.

## Run

Open one terminal in each service folder and run:

```text
mvn spring-boot:run
```

Start Eureka first, then the other services, and finally the frontend:

```text
cd frontend
npm run dev
```

Open the URL shown by Vite. The frontend calls the API Gateway on port `8085`.

## PostgreSQL setup

Install PostgreSQL, then create the database once:

```sql
CREATE DATABASE talentsync;
```

Or, if Docker is installed, run `docker compose up -d postgres` from the project root. This creates PostgreSQL with the default settings automatically.

Start PostgreSQL before starting the Auth, Job, and Application services. Spring Boot creates the tables automatically on first run.

If RBAC was added after an older database already existed, run once in pgAdmin:

```sql
ALTER TABLE users ADD COLUMN IF NOT EXISTS approved BOOLEAN NOT NULL DEFAULT TRUE;
ALTER TABLE users ADD COLUMN IF NOT EXISTS recruiter_requested BOOLEAN NOT NULL DEFAULT FALSE;
UPDATE users SET role = 'JOB_SEEKER', approved = TRUE WHERE role = 'CANDIDATE';
```

## Main API examples

```text
POST /api/auth/register
POST /api/auth/login
GET  /api/jobs
POST /api/jobs
GET  /api/applications
POST /api/applications
GET  /api/recruitment/pipeline
```

JWT tokens are returned by register/login. The signing key is in `auth-service/src/main/resources/application.properties` and should be changed for production.

## Role-based access

New registrations are always created as approved `JOB_SEEKER` accounts and can log in immediately. A job seeker can request recruiter access from Settings; an admin must approve that request. No role dropdown is shown during signup.

Default admin login:

```text
Email: admin@talentsync.com
Password: admin123
```

Use the admin token with:

```text
GET /api/admin/users
PUT /api/admin/users/{email}/approve?role=JOB_SEEKER
PUT /api/admin/users/{email}/approve?role=RECRUITER
```

Send the header `Authorization: Bearer ADMIN_TOKEN`. A pending user cannot log in until approval.

## Backend evaluation checklist

### 1. Problem analysis and requirements

TalentSync supports corporate job posting, candidate applications, application status tracking, recruiter approval, and admin-controlled access.

### 2. Microservices and discovery

| Service | Port | Responsibility |
|---|---:|---|
| Eureka Server | 8761 | Service registration and discovery |
| Auth Service | 8081 | Users, BCrypt passwords, JWT, RBAC, admin approval |
| Job Service | 8082 | PostgreSQL job CRUD |
| Application Service | 8083 | PostgreSQL applications and pipeline counts |
| Recruitment Service | 8084 | Recruitment health service |
| API Gateway | 8085 | Routing, CORS, Eureka load balancing, JWT authorization |

### 3. JWT and RBAC

Auth Service creates signed JWT tokens. The Gateway validates the token before forwarding protected requests.

| Request | Required role |
|---|---|
| Register/login/jobs list/pipeline | Public |
| Create/update/delete job | RECRUITER or ADMIN |
| Submit application | JOB_SEEKER |
| Change application status | RECRUITER or ADMIN |
| Admin user approval | ADMIN |
| Request recruiter access | JOB_SEEKER |

Invalid or missing tokens return `401`. Valid tokens with the wrong role return `403`.

### 4. API Gateway

Gateway routes are defined in `api-gateway/src/main/java/com/klu/api_gateway/GatewayRoutes.java`. `JwtGatewayFilter.java` validates JWTs and applies role checks. Eureka resolves each `lb://service-name` route.

### 5. PostgreSQL persistence

The Auth, Job, and Application services use Spring Data JPA and PostgreSQL. Tables are created or updated using `spring.jpa.hibernate.ddl-auto=update`.
